## 三、逐模块处置细化

### 3.1 直接保留（新方向直接受益）

| 模块 | 处置 | 理由 |
| --- | --- | --- |
| `core/` 主题三件套 + 门禁 | 保留 | 精品赛博审美与"200 个惊艳用户"的工程底座，圣经明确保留 |
| `core/database/` `storage_service.dart` | 保留 | 纯本地存储契合"数据隐私"红线与陪伴路线 |
| `features/library/` | 保留 | 文件导入（Isolate/GBK/取消令牌）是"拖本书进来"场景的全部工程基础 |
| `features/reader/` | 保留 | 降级为"陪你读"表演舞台，正文/提词器/章节机全部现成 |
| `features/game_2048/` | 保留 | 降级为"陪你玩"；`tile_widget` 高分彩蛋、战绩截图美学是传播机制素材 |
| `features/settings/` | 保留 | 新增"安静模式"开关的最小挂载点（圣经 2.5 铁律三：毒舌要有关机键） |
| `features/update/` | 保留 | 发版基础设施，与方向无关 |
| `server/`（Go 后端） | 保留现状 | 用户决策：西游记分发与云端 TTS 继续服务，后续按台词/语音验证结果再评估 |

### 3.2 需改造（核心工作面）

## 四、对下一步的资产就绪度结论

圣经行动项二（50 句台词）与行动项三（两个场景做真东西）所需的工程资产**全部就绪，零新增依赖**：

```text
首次启动场景  = dashboard 首屏（改） + companion 语义/触发器（有） + 空书架（library 有）
深夜读书场景  = reader 正文流（有） + 空闲计时器（TTS idleTimeout 有） + ambient 氛围音（有）
台词承载      = xiaoyo_semantics 语义契约 + CyberToast 拟人气泡（已有 PFP 集成）
性能护栏      = RepaintBoundary / Transform 红线（既有门禁自动拦截）
```

**结论**：盘点推翻了"需要大规模重写"的隐忧。圣经 4.3 表中唯一的"砍"建议（author）降级为
"冻结"即可，`server/` 保留现状后，整个 XIAOYO 世界的搭建是**增量改造，不是推倒重来**。
