# 20260813 阶段 0 落地差距评估

## 背景

项目此前获得一份「阶段 0 审批方案」（四周、34 人日、外部现金上限 20,000 元），
方案声称工程侧已具备若干前置产物（PROD-00、PERF-0-A、可点击手机 HTML 原型、
Xiaoyo 候选概念图），并要求在四周内完成真实用户访谈、真实支付实验、真机性能
基线与 IP-0 资产验收。用户判断"目前工作区的内容根本落地不了"。

本报告对工作区真实状态进行逐项核查，区分：

- **当前事实**：由仓库文件、代码、测试与文档可验证的状态。
- **建议目标**：详设中推荐但尚未验证的架构或验收指标。
- **商业假设**：必须由真实用户行为与真实支付才能证明的结论。

本报告不修改业务代码，只做证据核查与差距评估。

## 结论三：用户"落地不了"的判断成立，卡在结构层面

把阶段 0 交付物按"代码能否独立完成"切分：

| 阶段 0 交付物 | 工作区现状 | 本地能否闭环 |
| --- | --- | --- |
| 可点击手机 HTML | 完成 + 浏览器验收 | 已完成 |
| 成长 + 印记 + 荣誉 | 领域代码已实现 | 已完成 |
| PROD-00 开关/回滚 | 已实现 | 已完成 |
| 免费/付费书境规则 | 仅只读预览 | 部分 |
| PERF-0 真机基线 | 工具齐备但无设备 | 需要一台 Android 真机 |
| 24 次访谈 / 40 次有效体验 | 无用户渠道 | 需要真实用户 |
| 240–300 合格访问者 | 无流量渠道 | 需要用户来源 |
| Local Pro 订金 / 书境包全款 | 无合规商户 + 退款能力 | 需要商户资质 |
| 作者听校 49 元实验 | 仅本地仓储 | 需要作者样本 |
| Xiaoyo 四视图/表情/材质/动作 | 仅 1 张候选图 | 需要设计师 |
| 原创近似检查 + 授权链 | 仅有门禁清单 | 需要资产/法务方 |
| 基础 Rive 动效样例 | 无原创 .riv | 需要动画师 |

由此得到结构性判断：

1. **工程侧确实落地了**：代码、测试、门禁、契约检查真实存在且自洽，全量测试
   与静态检查按文档记录均通过。
2. **阶段 0 的核心是商业验证，不是工程验证**：而商业验证的关键交付物（真实用户、
   真实支付、真机性能、原创 IP 资产）没有一项能由代码仓库独立完成，全部依赖
   仓库之外的外部资源。
3. **工作区把"工具"做齐了，但工具不等于数据、不等于结果**：`commerce_experiment_
   evaluator.dart` 在没有真实台账输入时输出永远是 `insufficientEvidence`；
   `run_android_profile.ps1` 在没有设备时无法产生任何基线；`check_xiaoyo_ip0.dart`
   在六类证据缺位时始终报告未就绪。工具越严谨，越说明"数据尚未进入"。
4. **方案默认存在执行主体**：34 人日、2 万现金、四周，隐含团队、预算与审批流程；
   从工作区只能看到工程产出，看不到任何外部资源投入迹象。阶段 0 的执行前置条件
   （人、钱、资质、设备、流量）全部在工作区之外——这正是"落地不了"的准确含义。

## 结论四：如果推进，可行的拆法

阶段 0 按"本机 + 最低外部依赖"重排优先级：

1. **可立即做**（唯一"一台设备就能闭环"的硬门）：借/购一台 Android 真机
   （千元档即可），按 `docs/performance/baselines/README.md` 执行两轮同设备采集，
   用 `compare_baselines.dart` 生成脱敏对比报告，完成 G0 签署。
2. **可小成本做**：把 24 次访谈压缩到 5–10 位真实陌生人（非朋友），只验证
   "听读 + 2048" 是否有真实吸引力，替代全量商业实验。
3. **必须等外部资源**：真实支付实验（商户资质 + 退款能力）、IP-0 六类资产
   （设计师/动画师/法务）、作者听校（作者样本）。三者在资源到位前无法启动，
   继续堆文档不会改变其状态。

## 决策建议

- 阶段 0 的"工程前置"部分已达标，可以作为谈判基础，但不应被描述为"商业验证
  已完成"。
- 四周 34 人日的原始方案在无外部资源投入的情况下不可执行；建议先按结论四的
  优先级 1 与 2 落地最小闭环，用真实行为数据决定是否投入商户资质与 IP 资产。
- 保持"免费核心路径 + 本地数据 + 开关默认关闭"的既有边界，直至真实支付门
  与 IP-0 门通过。
