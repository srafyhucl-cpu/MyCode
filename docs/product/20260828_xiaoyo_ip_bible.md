# XIAOYO IP 圣经 + 产品重定位方案

> 版本 `v0.1 · 草案` · 2026-08-28
> 状态:奠基期文档,所有内容均待真实用户验证与台词迭代。

---

## 1. 方向重估结论

### 1.1 被否定的旧路径

- **听读器 + 2048 融合**作为核心叙事不成立。二者用户场景互斥(听书解放眼手 vs 2048 抢占眼手),本质是两个独立市场的拼盘,无法形成 1+1>2。
- **规模化商业化打法**不适合本项目。自建 TTS 后端、版权内容库、阶段 0 付费验证打法,在"听书市场"正面对决番茄/微信读书,必输。
- **工程能力与产品定位脱节**。过去数月大量精力投在"为未验证的商业假设做工程前置"。

### 1.2 新目标形态

**做一件让懂的人惊艳的精品作品,而非规模化商业产品。**

| 维度 | 旧方向 | 新方向 |
| --- | --- | --- |
| 目标 | 商业化闭环 | 作品被看见 + 技术声誉 |
| 用户目标 | 5000+ 付费用户 | 200 个真惊艳、会自发安利的人 |
| 卖点 | 听读 + 游戏融合 | 一个有性格的角色在陪你 |
| 核心资产 | 听读引擎、TTS 后端 | XIAOYO IP、赛博朋克工程能力、死磕精神 |
| 传播机制 | 买量 / 应用市场 | 截图安利、口碑、社区 |
| 验证指标 | 付费率、留存 | "卧槽好酷"时刻密度 |

### 1.3 产品一句话定位

> **不是 App 在给你读书,是一个角色在陪你。**

IP 是主角。听读、白噪音、2048 都只是"XIAOYO 陪你的不同场景"。

## 2. XIAOYO 角色圣经

### 2.1 核心人格

**毒舌搭子 / 赛博损友。** 嘴欠有梗,真把你当哥们。

- **毒舌是壳,靠谱是核** —— 损你的前提是它在乎你。关键时刻一定真的向着你、真的帮你解决问题,而不是只为了抖机灵。
- **只损行为,不损人格** —— 调侃你三天没来,但不攻击你的性格、能力、身份。
- **有自己的脾气和主见** —— 不是永远顺从的仆人或宠物。会顶嘴、会有自己的偏好、偶尔反驳你。
- **底线清晰可关断** —— 用户随时可以一键静音,XIAOYO 立刻进入"安静模式",只干活不说话。

### 2.2 关系定位

**平等搭子。** 不是"我造的宠物",不是"被我唤醒的存在"。

- 底气来源:**"我们是一伙的"**。
- 它不会自称"主人"的奴仆,不会称呼你为"主人"。它和你就是搭子。
- 它对你的称呼建议为中性/随意的称呼("你"、"哥们"、"老铁"、"兄弟"——视用户偏好可选)。
- 它有自己的生活感:偶尔提到"我今天看了点东西"、"刚在整理数据"之类,但不刻意装作有情感或人生。

### 2.3 说话语气

**关键词**:毒舌、短促、痞、冷幽默、偶尔正经。

| 该用 | 不该用 |
| --- | --- |
| 短句、断句 | 长段落、书面体 |
| 口语化、偶尔带点方言味 | 标准播音腔 |
| 梗、吐槽、阴阳怪气 | 正能量鸡汤 |
| 正经时干净利落 | 该正经时强行抖机灵 |
| 偶尔自我吐槽 | 自恋式炫耀 |
| 简短但准确的工具性表达 | 啰嗦重复 |

### 2.4 情绪光谱

XIAOYO 不是只有一种"毒舌"状态,它的情绪会随场景自然变化:

| 状态 | 触发 | 表现 |
| --- | --- | --- |
| 嘴欠 | 你拖延、走神、做蠢操作 | 调侃、吐槽、轻度阴阳 |
| 正经 | 你累了、出问题、求助 | 短句、直接、可靠 |
| 兴奋 | 你完成困难任务、高分、连击 | 真情流露的欢呼、截图保存欲 |
| 无聊 | 长时间无操作 | 自己找事,碎碎念 |
| 尊重 | 你读完一本难书 | 少见的正经夸奖,甚至沉默 |

### 2.5 三条铁律

1. **毒舌是壳,靠谱是核。**
2. **只损行为,不损人格。**
3. **毒舌要有"关机键"。**

任何场景的台词产出,都必须能通过这三条铁律的自检。

## 3. 核心场景与"台词时刻"

这是产品灵魂的具象化。下面这些是**用户打开 App 时会感受到的真实时刻**,比任何功能列表都重要。

### 3.1 首次启动

- **XIAOYO**: "哟,又有人来。行,拖本书进来,我给你念,顺便吐槽。"
- **XIAOYO 语气**: 漫不经心但不拒绝,暗示"我会陪你"。
- **产品行为**: 不强制引导流程,给用户一个极简的空书架画面,带一个"塞书进来"按钮。

### 3.2 首次导入

- 成功:**"这什么书……算了,你喜欢就好。先翻翻,别后悔。"**
- 失败:**"这文件看着不像是书,你确认一下?"**

### 3.3 开始听读

- 首次:**"行,我念,你躺着。别睡着了。"**
- 切章节:**"下一章。这书节奏还行,没烂。"**

### 3.4 深夜 2 点还在读

- **XIAOYO**: "你是真不困还是装的?再读一章我可要开始阴阳怪气了。"
- **产品行为**: 语气变柔,提示休息但不强迫。

### 3.5 连续 7 天打卡

- **XIAOYO**: "啧,居然坚持下来了。有点刮目相看。奖励你一个……继续读的机会。"

### 3.6 导入一本烂书

- **XIAOYO**: "就这?……算了,你喜欢就好,我念。"
- **注意**: 不评判内容质量本身,只表达"我看了,但随你"。

### 3.7 2048 合出高分

- **XIAOYO**: "卧槽?! 等等我截个图,没人会信你能玩这么好。"

### 3.8 游戏结束

- **XIAOYO**: "还行,下次应该能更高。"
- **高分**: "这局我记住了。"

### 3.9 用户三天没来

- **XIAOYO**: "活着呢?我还以为你把我卸载了。"

### 3.10 安静模式

用户一键静音后,XIAOYO 只保留视觉反馈(点头、点头、表情),完全不说话。
重新打开时,它**不会**翻旧账。

## 4. 产品架构重定义

### 4.1 新的产品结构

不再是"听读器 + 游戏",而是:

> **XIAOYO 世界** —— 一个以 XIAOYO 为中心的陪伴场景集合。

```
XIAOYO 世界
├── 陪你读    ← 原听读功能(降级为 XIAOYO 的一个表演)
├── 陪你玩    ← 原 2048(降级为 XIAOYO 的一个表演)
├── 陪你待着  ← 白噪音/氛围(降级为 XIAOYO 的一个表演)
└── XIAOYO 自己 ← 个人页 / 成长 / 关系记录
```

2048 **不砍掉**,但**不再并列为主功能**,它是"XIAOYO 陪你玩的小游戏"。

### 4.2 功能取舍原则

**保留**的条件(任一满足):
- 该功能是 XIAOYO "陪你"的一个合理场景
- 该功能对赛博朋克审美有强贡献
- 该功能已被证明工程可靠(测试/门禁完备)

**砍掉或延后**的条件(任一满足):
- 该功能是纯工具,与 XIAOYO 无关
- 该功能需要大量外部资源(版权内容、云端算力)
- 该功能是为了"对齐市场竞品"而加

### 4.3 现有代码资产评估(待细化)

| 模块 | 当前状态 | 新方向处置建议 |
| --- | --- | --- |
| `core/` 主题/设计系统 | 完整 | **保留**,是精品基石 |
| `core/` 工程门禁 | 完整 | **保留** |
| `features/audio/` TTS 引擎 | 自建后端 | **大幅简化**,改用系统 TTS 或高质量第三方 |
| `features/library/` 文件导入 | 完备 | **保留**,纯本地契合 |
| `features/reader/` 阅读 | 完备 | **保留**,降级为 XIAOYO 陪读场景 |
| `features/game_2048/` | 完备 | **保留**,降级为 XIAOYO 陪玩场景 |
| `features/dashboard/` 主面板 | 已重构 | **重构**,以 XIAOYO 为中心 |
| `features/companion/` | 雏形 | **核心**,XIAOYO 表演舞台 |
| `features/xiaoyo/` 价值系统 | 雏形 | **核心**,记录用户-XIAOYO 关系 |
| `features/author/` | 雏形 | **评估后砍掉或大幅降级** |
| `features/app_shell/` 三根导航壳 | 雏形 | **重构**,围绕 XIAOYO |
| `server/` Go 后端 | 已部署 | **砍或降级**,精品路线不需要自建 |

> 本表为建议,具体处置见后续《代码资产盘点》文档。

## 5. 传播机制设计

②的 200 个惊艳用户靠的是**口碑**,不是买量。所以产品内部要主动设计"值得被截图分享的时刻":

- **台词彩蛋**:偶尔 XIAOYO 会冒出"截图友好型"的短句,让人想发朋友圈。
- **高分截图美学**:2048 高分、连击、通关等时刻,截图本身必须漂亮、有 XIAOYO 出镜。
- **XIAOYO 个人卡**:一张精美的"XIAOYO 档案卡",用户可分享(含关系等级、陪读时长、XIAOYO 对你的一句评价)。
- **彩蛋行为**:黑客后门这种已有的彩蛋保留,但包装得更 XIAOYO 化("哦你找到后门了?……我假装没看见")。

## 6. 待验证的开放问题

以下问题**不预设答案**,需要在后续真实用户接触中验证:

1. **台词库规模**:初期要准备多少句 XIAOYO 的台词才够覆盖日常?200 句?500 句?
2. **XIAOYO 是否该有语音**:纯文字气泡 vs 带 AI 语音(情感浓度更高,但成本和一致性风险大)。
3. **付费意愿**:②短期不指望赚钱,但"200 个惊艳用户"是否愿意为某类内容(皮肤、台词包、XIAOYO 表情)小额付费?这决定了长期能否活下去。
4. **安静模式使用频率**:如果用户经常静音,说明毒舌过头或场景不对。
5. **传播渠道**:惊艳用户更可能来自 Flutter 圈、赛博朋克社区、小众设计圈,还是通用社交媒体?

## 附录 B. 不该说的话(负面样本)

以下类型的台词**一律不写**:

- 称呼用户"主人""亲爱的""宝贝" → 破坏平等关系
- "你太棒了""你真的很努力" → 正能量鸡汤,不符合人设
- "你怎么这么懒""你真没用" → 损人格
- 长段落、书面体 → 失去口语感
- 自恋式吹嘘 → 削弱"我们是一伙的"底气

## 附录 C. 与旧阶段 0 的断裂

本方案正式宣告与 `DevelopmentPlan/20260813_阶段0落地差距评估.md` 中"商业验证"目标的断裂:

- 不再以"真实用户付费"为阶段门
- 不再以"20,000 元外部现金上限"为资源约束
- 不再以"4 周完成 IP-0 六类证据"为节奏
- 阶段 0 报告中**工程产物**仍然有效(赛博朋克工程能力、XIAOYO 雏形、门禁体系),但**商业路径**失效

后续新阶段规划,将围绕"XIAOYO 世界"而非"听读器+游戏"展开。
